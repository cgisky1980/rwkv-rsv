# 后端统一抽象 — S1 实施记录

> 日期：2026-08-07
> 状态：S1 完成（trait 接口 + Vulkan 实现，抽象层验证通过）

## 1. 目标

后端统一抽象第 1 阶段：引入平台无关张量句柄 `TensorId` 与算子级 `ComputeBackend` trait，
将现有 Vulkan `Runtime` 封装为 `VulkanBackend`，用真实 GPU 算子验证抽象层可用。

## 2. 改动

| 文件 | 内容 |
|---|---|
| `src/backend.rs`（新增） | `TensorId`、`TensorDtype`、`BackendKind`、`ComputeBackend` trait、`VulkanBackend`、`detect_backend()` |
| `src/lib.rs` | 注册 `pub mod backend;` |

## 3. 抽象层设计落地

- **`TensorId(u32)`**：平台无关句柄，后端内部 `HashMap<TensorId, VulkanTensor>` 映射到设备张量。
- **`TensorDtype`**：`F32 / F16 / U32`，创建时决定张量类型，算子内校验类型。
- **`ComputeBackend` trait**（首期核心算子）：
  - 张量管理：`create_tensor(len, dtype)`、`upload`、`download`
  - 批处理：`begin_batch` / `end_batch`
  - 算子：`gemv_f16`、`norm`
- **`VulkanBackend`**：持 `Runtime` + 张量映射表；`gemv_f16`/`norm` 通过 `TensorId` 查表转调 `Runtime`。
- **`detect_backend()`**：CUDA 可用 → Cuda，否则 Vulkan（当前 `cuda_available()` 恒 false）。

## 4. 关键实现要点

- **借用处理**：算子输出张量 `y` 需可变引用，从 `HashMap` 用 `remove` 取出为 owned，执行后 `insert` 放回；
  输入张量用 `get` 不可变引用，规避同一 map 的 `get`/`get_mut` 借用冲突。
  （`HashMap` 无 `get_many_mut`，故采用 remove/insert；若改用 `indexmap` 可更简洁。）
- **`U32` 变体预留**：any4/int8 量化张量由后续算子消费，当前核心算子集未使用其字段，加 `#[allow(dead_code)]`。
- **`too_many_arguments`**：算子签名沿用 Runtime 扁平参数约定，trait 方法加 `#[allow(clippy::too_many_arguments)]`。

### 新增单元测试（`backend.rs` 内 `#[cfg(test)]`）

| 测试 | 验证内容 |
|---|---|
| `backend_gemv_f16_ones` | gemv_f16：A 全 1 → y[m]=K（m=1024, n=1, k=256） |
| `backend_norm_matches_reference` | norm：逐 batch 行归一化 + affine，与 CPU 参考一致（c=256, h=1, rows=4） |

> 注意：gemv 的 M 需足够大（shader 每 workgroup 处理 ROWS=4 行，小 M 如 64 会输出 0），
> 测试用贴近真实模型的 m=1024。参见 `gemv_f32io.comp` 的 `ROWS` 常量。
