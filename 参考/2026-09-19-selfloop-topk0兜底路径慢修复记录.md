# selfloop topk=0 兜底路径性能灾难修复记录（2026-09-19）

> 关联计划：[rwkv-rsv并发吞吐对齐信天翁计划.md](file:///c:/work/ai00-x-dev/.trae/documents/rwkv-rsv并发吞吐对齐信天翁计划.md)（Phase 4 采样内核压榨的前置必修）
> 关联文件：[backend_cuda.rs](file:///c:/work/ai00-x-dev/rwkv-rsv/src/backend_cuda.rs)

## 1. 现象

selfloop 自循环解码下，`rwkv_sample` 采样内核的**无 top-k 路径**（`top_k == 0`，走 top-p 兜底）性能灾难性劣化：

| 路径 | 单流 decode | 批量 B=8（聚合） |
|---|---|---|
| `TOPK=50`（快速路径） | ~85 tok/s | ~128 tok/s |
| `TOPK=0`（兜底路径） | **~20.6 tok/s** | 严重劣化 |

同一模型、同一数据、同一 `top_p`，仅因 `top_k` 参数不同就出现 4 倍差距 —— 显然是实现 bug 而非算法代价。

## 2. 根因（三处，均为 BS=112 非 2 的幂 + 累积方向问题）

### 根因 A：do_topk 兜底归约的"孤儿索引"bug（单/批量 kernel 各一处）

`top_k == 0` 时没有全局 top-K 列表可用，需在全词表上求**第 (K) 大值作为阈值**。原实现用纯树归约：

```cuda
for (int step = BS >> 1; step > 0; step >>= 1) { ... }
```

BS=112 **不是 2 的幂**，step 序列为 `56, 28, 14, 7, 3, 1`。在 `14 → 7 → 3 → 1` 段，索引 6 与 2 的结果不再被任何后续 step 合并 —— 成为**孤儿**。后果：`s_fval[0]` 只是约 1/16 元素的最大值，**阈值系统性偏低**。

### 根因 B：top-p 快速路径累积方向反了

`s_sortedidx` 是**降序**（`[0]` 最大），但旧代码从 `K-1`（最小）起累积，与其自身注释「从最大概率起累积」直接矛盾。后果：截断阈值偏低 → 保留集合偏大 → 多峰分布下与兜底路径结果**不一致**。

### 根因 C（性能主犯）：top-p 兜底每轮只取 1 个候选

旧兜底实现是「每轮全词表 `reduce_max` 取 1 个最大值 → 标记 → 下一轮」，512 上限意味着最坏 **512 轮 × 全词表扫描**。平坦分布（高温度）下实测 **51.8 ms/token**。

> 注：根因 A 会放大 C 的轮数 —— 阈值偏低导致需要更多轮才能累积到 `top_p`。

## 3. 修复

### 3.1 归约改「P2 折尾 + 2 幂树」（根因 A）

与 softmax 既有写法保持一致：先把尾部 `[P2, BS)` 折进 `[0, BS-P2)`（`P2 = 64` 为 ≤BS 的最大 2 幂），再做 2 幂树归约，杜绝孤儿。带索引的 max 归约用 `(值降序, 索引升序)` 打破平值并列。

### 3.2 top-p 累积方向纠正（根因 B）

从 `[0]`（最大）起累积。

### 3.3 兜底改「每轮取 BS 个候选」（根因 C）

新增设备函数 `sample_top_candidates`（单/批量 kernel 各一份）：从 `mask == 0` 的剩余项中并行取出最大的 BS 个候选，按 `(值降序, 索引升序)` 做 **O(BS²) 并行定秩**排序后输出。

- 无需为 112 元素引入位排序 —— 每线程只扫 BS 个 shared 元素即可定秩。
- 空槽必须给**唯一哨兵索引**（`n + tid`），否则多个 `(-1e30, 0)` 撞秩导致排序结果错乱。
- 全块协同（内含 `__syncthreads`），必须所有线程统一调用。

512 候选上限现在只需 **≤5 轮**（旧版 ≤512 轮）。

### 3.4 退出条件必须全块统一（死锁修复）

循环退出条件（`s_done`）必须放 **shared** 而非 thread-local：否则 `tid0` 先越过 `top_p` 退出循环、其余线程继续跑，`__syncthreads` 分歧 = **块内死锁**（kernel 永久自旋占满 99% SM）。新增 shared 变量 `s_consumed` / `s_used` / `s_done`（两 kernel 均加）。

## 4. 验证

### 4.1 等价性

固定 seed + `top_p=0.2` + `temp=1.0`：`TOPK=50` 与 `TOPK=0` 产出**逐 token 相同**的序列，且同速（84.3 vs 83.8 tok/s）。

### 4.2 性能（`SEGS=4 NTOK=64 WARMUP=1 TEMP=1.0`）

| 路径 | 单流 | 批量 B=8（聚合） |
|---|---|---|
| `TOPK=50` | 92.2 tok/s | 127.8 tok/s |
| `TOPK=0` | 95.9 tok/s | 131.5 tok/s |

单流兜底路径 **20.6 → 95.9 tok/s（≈4.7×）**，且两路径已无实质差距。最坏平坦分布（`TEMP=4/12`）仍保持 ~90 tok/s。

`cargo fmt --all` / `cargo clippy --all-targets -- -D warnings` / `cargo test --release` 全绿（59 passed, 1 ignored）。

## 5. 教训

1. **非 2 的幂 block size 的树归约必须折尾** —— BS=112 是反复踩坑点（softmax 已修过一次，do_topk 又漏）。凡 `step >>= 1` 的归约都要检查。
2. **NVRTC 内核源码在 Rust 字符串里，`cargo build` 抓不到内核逻辑错误** —— 必须 `cargo run` 实测。
3. **shared 变量做循环退出条件**是块内死锁的经典陷阱，条件判断必须在 `__syncthreads` 前对全块可见。
4. **累积方向要对着数据结构语义写** —— 降序列表从 `[0]` 起，注释与代码矛盾时以数据语义为准。
