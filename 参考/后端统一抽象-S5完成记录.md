## 2. 实现内容（`src/backend_cuda.rs` 补齐）

### 2.1 序列 / 矩阵算子（S5 新增，对齐 Albatross / Vulkan shader）

| 算子 | 语义 |
|---|---|
| `gemm` / `gemm_bias` / `gemm_add` / `gemm_relu2` / `gemm_tanh` | fp16 输入 tensor-core GEMM（f32 累加/输出），带 bias/残差/激活变体 |
| `gemm_any4` | any4 原生态 GEMM（ANY4_GEMM_PREFILL 备用路径），可选 relu² |
| `to_f16` / `to_f16_triple` | 跨步 fp32→fp16 转换（prefill token 并行），支持三输入融合 |
| `dequant_any4_to_f16` / `dequant_int8_to_f16` | 反量化到 fp16 scratch 供 GEMM 消费 |
| `elementwise_sigmoid(_inplace)` | f32 token 并行 sigmoid |
| `fuse_ka` | k_mod / kk_l2 / b 融合（非融合版，seq 用） |
| `sum_rk_rk` | y += sum(r*k_mod*r_k) * v，按 head 归约 |
| `seq_shift` | token shift + time-mix 插值（seq 用） |
| `dplr_seq` | DPLR 状态更新（seq 用，内部循环 T） |
| `elementwise_scale_exp` | y = exp(a * b[0])（w 衰减因子） |
| `elementwise_mul` | y = a * b |
| `v_first_lerp` | v += gate*(v_first - v) |
| `gemv_seq` | f32 权重跨步批量 gemv（GEMM_DIAG 参考） |
| `copy_device` / `copy_token` | f32 设备侧拷贝 / 行拷贝 |
| `gemm_dispatch` | 统一 GEMM 变体调度（bias/res/act 组合） |

### 2.2 buffer 管理算子

| 算子 | 语义 |
|---|---|
| `clear_cache` | 清空 kernel 缓存（seq T 变化重建缓冲后调用） |
| `drop_host` | 释放 host 缓冲 |
| `store_sampler_host` / `sample_into_host_seeded` / `record_token` / `argmax_into_host` | self-loop 采样 host-visible 缓冲链路 |

### 2.3 关键 kernel 设计

- **统一 `gemm_dispatch`**：`gemm`/`gemm_bias`/`gemm_add`/`gemm_relu2`/`gemm_tanh` 收敛为单一
  GEMM kernel，按 `bias`/`res`/`act`（relu²/tanh）组合调度，f32 累加、fp16 输入。
- **seq 路径拆分算子**：`seq_shift` + `fuse_ka` + `dplr_seq` + `sum_rk_rk` 于 fp32 完成，
  与 tok 的 `norm_lerp6` + `fuse_ka_dplr_norm` 融合版数学等价，仅中间精度不同（fp32 vs fp16）。
- **self-loop 采样**：`argmax_into_host` / `sample_into_host_seeded` + `record_token` 在 GPU
  侧闭环，token 索引写 host-visible 缓冲，避免 CPU-GPU 往返采样。

## 4. tok (decode) vs seq (prefill) 精度说明

- **tok（decode）**：`lowrank_chain4` 输出 a/v/w 为 **fp16**，`fuse_ka_dplr_norm` 以 fp16 中间量
  完成 DPLR 状态更新 —— 与 **Albatross decode 的 fp16 融合**一致。这是 decode 的正确基准。
- **seq（prefill）**：`seq_shift`/`fuse_ka`/`dplr_seq` 于 **fp32** 完成 a/v/w，与 CPU fp32 参考
  逐位接近（0.0436）。
- 两路径对拍 max_abs_diff≈0.04（单 token），跨 token 后经 layer_norm 放大（tmix_x 可达 0.1~0.2），
  属 **fp16 中间精度的预期累积**，非算法差异；不影响 top-1 argmax 与 self-loop 序列一致。
- 结论：decode 走 tok（对齐 Albatross fp16 融合），prefill 走 seq（对齐 CPU fp32），两条路径
  **数学等价、精度均正确**。

## 5. 关键设计决策

- **以 Albatross faster3b 为主参考**：融合 kernel（norm_lerp6 / fuse_ka_dplr_norm / gemv_rkv_stage1）
  语义与 `rwkv7_mega_ops_260602.cu` 逐位对齐；decode 中间量沿用 fp16，与信天翁一致。
- **统一 gemm_dispatch**：5 种 GEMM 变体收敛为单一 kernel，按 bias/res/act 组合调度。
- **`CUDA_READY = true`**：全算子就绪，`detect_backend()` 自动优先 CUDA。
- **CUDA 上下文全局锁**：`CUDA_CTX_LOCK` 串行化 primary context 访问，多线程测试安全。
