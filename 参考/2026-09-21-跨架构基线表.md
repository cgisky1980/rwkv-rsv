### 1.1b 机器可达上限（独立 nvcc 探针，2026-09-21）

| 项 | 读数 |
|---|---|
| 纯流式读 `uint4`（grid 8192×256） | **503~506 GB/s** |
| 纯权重读（`gemv_variant_mb` 同访存形态，权重读 2 遍） | 0.0992 ms / **528 GB/s** |
| `gemv_variant_mb` 完整内核（同形态） | 0.2081 ms / **252 GB/s** |

⇒ **权重读模式本身能跑满带宽；掉速来自「读 x + int8 反量化 + hfma2」。**
本机「可达上限」按 500 GB/s 记（非 616）。详见
[batch线性层第二代实施记录](file:///c:/work/ai00-x-dev/rwkv-rsv/参考/2026-09-21-batch线性层第二代实施记录.md)。

**读数要点**：
- **B=1 走单流内核 `gemv_variant`，B≥8 走批量内核 `gemv_variant_mb`（BGRP=4）——是两个不同内核**，
  B=1 列不能当成纯 B 标度基线。
- 同一份权重访问模式：**单流 224~384 GB/s vs 批量 42~119 GB/s，效率差 3~5 倍**。
- 批量列按 `ceil(B/BGRP)` 折算真实带宽（B=8 → ×2，B=16 → ×4）：B=8 真实约 216~238 GB/s，
  B=16 真实约 168~232 GB/s。仍明显低于单流。
- FMA 峰值占用（B=8）实测仅 **12%** ⇒ 既不是带宽饱和也不是算力饱和。
- ⚠️ 上面「单流 vs 批量效率差 3~5 倍」的归因**已被 2026-09-21 探针修正**：批量内核
  慢不是因为权重读得慢（纯权重读同形态 528 GB/s），而是因为**激活 x 被重复读 + 元素级
  int8 反量化**；见 §1.1b 与[第二代实施记录](file:///c:/work/ai00-x-dev/rwkv-rsv/参考/2026-09-21-batch线性层第二代实施记录.md)。

> 渠道：**split-K**（`IM_KSPLIT`）—— 小 batch 时 `grid.y = batch/BN = 1`，
> 块数只剩 `M/BM`（40~80 块喂不满 68 个 SM），而**每 block 吞吐被钉死在 ~90 GMAC/s**、
> **聚合吞吐随并发块数单调上升**（80→102 / 160→172 / 1024→232 GMAC/s/SM）。

> 本表的 B=64/256 数字为单次端到端测量，误差量级约 ±2%。

**验收基准就此确立：B=256 需 2874.3 tok/s（同机同模型同档）。**
判读见 §3；一句话：**B=1 持平、B=256 差 6.9×（现 3.2×），差距全在「每槽成本不随 B 摊薄」**。

### 1.3b batch 扩展性（隔离计时，2026-09-21 晚新增）★ 判读见 §3

`KB_ITERS=60 KB_REPEATS=3`；单位 ms/call，括号内为**每槽** ms。

## 3. 结论与对下一步的输入

> ★ 2026-09-21 晚更新（依据 §1.3b/§1.3c 与 B=256 消融）。**旧的「把有效带宽从 42~119
> GB/s 提到 224~384 GB/s」目标作废**——带宽从来不是约束。

1. **量化目标（新）**：批量线性层现在是「每份权重摊到的指令数」受限，不是带宽受限
   （有效权重带宽仅 177~198 GB/s，而同形态纯读探针可达 528 GB/s）。
2. **不能靠调几何**（已穷尽）：`BGRP` 4→8、`ROWS` 2/4/8/16、`blockDim` 128→256/512、
   权重 `uint4` 宽载入、4 路独立累加器、`__ldcg` 绕 L1——**全部无改善或更慢**。
   现行 `ROWS=4 / BGRP=8 / 128 线程 / 16 warps-per-SM` 是本结构最优。
3. **不能靠「x 只读一次」**：x 流量 ∝ 1/ROWS，但把 ROWS 抬到 8/16（x ÷2~4）实测**单调变慢**，
   因为代价是 BGRP 必须降（权重侧工作量 ∝ 1/BGRP，涨得更快）。
   ⇒ 计划文档里的「GEMM 分块让 x 只读一次」**不是**正确的下一步。
4. **唯二能动的载体**：① 计算单元 SIMT → **张量核**（int8 IMMA `m8n8k16` 或 fp16 WMMA）；
   ② 权重/激活数据类型（fp16 权重 ⇒ 无 `dequant` 这一整段）。
   这正是上游 `faster3a_2607` 快的原因（rows≤16 WMMA、rows 8~2047 cuBLAS TENSOR_OP、
   `DTYPE=fp16`），见 [全流程精细对比](2026-09-21-Albatross-faster3a_2607-全流程精细对比.md) §4.1。
5. **架构分叉预案**：sm_75 无 `cp.async`，但 **IMMA / fp16 WMMA 在 Turing 可用**（sm_70+），
   故张量核路线**不需要** sm_80 分档。
6. ★ **同机基线已建立（§1.2b）**：B=1 双方持平（1.09×），B=256 上游 6.86×。
   按 FLOP 口径：上游 **17.1 TFLOPS**（fp16 TC）/ 我们 **2.42 TFLOPS**（fp32 SIMT），
   比值 7.1× ≈ 端到端 6.86× ⇒ **差距是计算单元档位，不是带宽、不是几何、不是融合度**。
   带宽距离下限：上游 8×、我们 **145×**（int8 省了字节没省时间）。
