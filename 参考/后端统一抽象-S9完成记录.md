# 后端统一抽象 · S9 完成记录（int8 稀疏 FFN → int8 decode 突破 107 tok/s）

> 状态：S9 完成。本轮解决 int8 模型 decode 仅略快于 fp16 的根因——FFN value 投影
> 走稠密 `gemv_int8_add`（全量读权重），而 fp16 走稀疏 `ffn_value_sparse_add`
> （r2=relu² 约 96% 稀疏，只读非零列）。为 int8/any4 反量化出 fp16 平铺权重、
> 复用稀疏内核后，int8 decode 从 64 tok/s 提升到 **107.7 tok/s**（约 1.7 倍），
> 首次全面反超 fp16。
> 前置：S1~S8（后端抽象 + CUDA 算子 + decode/prefill 吞吐优化 + any4 向量化）已完成。

---

## 1. 目标

per-kernel profiling 显示 int8 模型 58.1% 时间花在 `gemv_variant`，且 FFN value 用稠密
`gemv_int8_add`（每层全量读 c×fh 权重），而 fp16 用稀疏 `ffn_value_sparse_add`（只读
r2 非零列，~4%）。int8 权重虽只有 fp16 一半，却因稠密 FFN value 空耗带宽，decode 仅
64 tok/s vs fp16 62.3 tok/s。

本轮为目标：让 int8/any4 也能走稀疏 FFN，与 fp16 对齐。

---

## 2. 优化内容

### 2.1 稀疏 FFN 平铺权重对三种量化统一构建（`gpu_model.rs`）

`load_ffn_value_tiled` 原只从原始 fp16 张量构建平铺布局。改为**按量化形式自动取源**：

- int8：读 `{key}.int8_idx/.int8_sz`，`dequant_int8` 反量化到 f32；
- any4：读 `{key}.any4_idx/.any4_lut/.any4_sz`，`dequant_any4` 反量化到 f32；
- fp16：读原始张量 `tensor_to_f32`。

再统一转置到 `[c, fh]`、按 `[f_block][c_block][f_local][c_local]` 平铺、上传 fp16
成为 `ffn_value_tiled`。

**关键点**：int8/any4 张量可能是 2D `[M,K]` 或 3D（group 打包如 `[M,K/128,128]`），
故 `M=shape[0]`，`K` 由展平字节按量化比特数反推（`K = idx_u32.len()*4/M` 或 `*8/M`），
与 `load_int8/load_any4` 的断言一致。

### 2.2 解码路由：稀疏优先，稠密兜底（`gpu_model.rs`）

```rust
let sparse_ok = self.backend.supports_sparse_ffn()
    && std::env::var("FFN_SPARSE_OFF").is_err();
// 稀疏可用且有平铺权重 → ffn_value_sparse_add
// 否则按 int8 → any4 → fp16 稠密路由
```

### 2.3 后端接口适配（`backend.rs` / `backend_cuda.rs`）

- `ffn_value_sparse_add` 的 `value_w16` 参数改为 `Option<TensorId>`：CUDA 忽略它
  （直接走稀疏内核）；Vulkan 默认实现仅在 Some 时退化为 `gemv_f16_add`。
- 新增 `supports_sparse_ffn()`：CUDA 返回 true，其余默认 false（Vulkan 等走稠密量化路径）。

## 3. 验证

### 3.1 正确性

- 新增单元测试 `ffn_value_sparse_matches_cpu`：稀疏内核 vs CPU 参考，`max_diff < 2e-2` 通过。
- 端到端对照：int8 模型 argmax 生成 32 token，稀疏路径与 `FFN_SPARSE_OFF`（稠密）路径
  输出 token 序列**逐位一致**。
- 全量单元测试 59 passed / 0 failed。

### 3.2 性能（RTX 2080 Ti，3B int8 / fp16，NTOKENS=512）

| 路径 | int8（S9 后） | fp16 | int8（S9 前，基准） |
|---|---|---|---|
| infer_tokens decode | **107.7** tok/s | 86.0 | 64 |
| argmax_selfloop | **117.2** tok/s | 93.4 | — |
| sample_selfloop | **95.2** tok/s | 78.6 | — |
| prefill | 775.2 tok/s | — | — |

int8 decode 首次全面反超 fp16（符合带宽减半预期）。

## 4. 遗留 / 下一步

- head 单 kernel 读取量仍最大（int8 已省 4×，若需进一步提升可考虑 int4 head）。
- prefill 仍相对慢（int8 775 tok/s），可参考 S8 分析继续做去反量化 / GEMM 融合 / CUDA graph。
- Vulkan 后端 int8 仍走稠密量化路径（无稀疏内核），未做稀疏化。
