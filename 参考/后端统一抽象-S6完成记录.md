## 1. 目标

在 S5 端到端对齐基础上优化两条路径的吞吐：

- **decode**：消除每 token 的 `cuLaunchKernel` 启动开销（258 次/层 × 32 层）→ CUDA graph 捕获重放；
- **prefill**：GEMM 从自定义标量 kernel 切到 cuBLAS tensor-core → 大幅提升 seq 吞吐；
- **gemv tile 调优**：decode 核心 gemv 的跨线程归约从共享内存全归约改为 warp shuffle。

统一参考：`参考/Albatross/faster3b_2606/cuda/rwkv7_mega_ops_260602.cu`
（Albatross 融合 kernel 权威实现）。

## 2. 实现内容（`src/backend_cuda.rs` / `src/backend.rs` / `src/gpu_model.rs`）

### 2.1 CUDA graph（decode 启动开销优化）

- `backend.rs`：`begin_graph_capture` / `end_graph_capture` / `graph_replay` 三个 trait 方法，
  默认 no-op，仅 CUDA 覆盖。
- `backend_cuda.rs`：动态加载 `cuStreamBeginCapture` / `cuStreamEndCapture` / `cuGraphInstantiate` /
  `cuGraphLaunch` / `cuGraphDestroy` / `cuGraphExecDestroy`，`CU_STREAM_CAPTURE_MODE_GLOBAL` 捕获
  整条 stream。
- `gpu_model.rs` `forward_argmax_selfloop_with_state`：
  首 token 捕获完整前向 kernel 序列（`selfloop_step`），之后每 token `graph_replay`，消除启动开销。
- 捕获期间禁用 `cuEventRecord`（stream 处于 capture mode），`begin_batch` 据此跳过剖析事件。

### 2.2 cuBLAS prefill GEMM

- 动态加载 cuBLAS（`cublas_create_v2` / `cublasSetStream` / `cublasGemmEx` / `cublasDestroy_v2`），
  `cublasSetStream` 绑定计算 stream 保证与其它 kernel 的序关系。
- `gemm_dispatch` cuBLAS 路径：`C = A @ B^T`（A/B 行主序 f16，C 行主序 f32）。
  利用 cuBLAS 列主序输出 `C_cm = B @ A^T`（形 [n,m]），`ldc=n` 即得行主序 C[m,n]：
  `(m_i,n_i,k_i)=(n,m,k)`，`transa=OP_T(权重 B)`、`transb=OP_N(输入 A)`、`lda=ldb=k`。
- epilogue kernel `rwkv_gemm_epilogue`：op 语义 0=纯 GEMM / 1=+bias / 2=+x / 3=relu² / 4=tanh。
- 环境开关：`CUBLAS=0`（禁用 cuBLAS 句柄）、`CUBLAS_GEMM=0`（保留句柄但 gemm 走自定义 kernel）、
  `CUBLAS_DIAG`（打印维度）用于隔离问题。

### 2.3 gemv tile 调优（warp shuffle 归约）

- 核心 decode gemv 族（同构 4 行 / 128 线程 block）的跨线程全归约
  （7 步 `__syncthreads` 树归约）改为 **warp shuffle 归约**（每 warp 内 `__shfl_down_sync`，
  仅 1 次 `__syncthreads`），对齐 Albatross `row1_linear_exact4_kernel<128,2>`：
  - `gemv_f16`（head 投影，M=vocab）
  - `gemv_variant`（FFN relu² / mul_add / add，wtype 分派）
  - `gemv_rkv_stage1`（fp16 r/k/v）
  - `gemv_any4_rkv_stage1`（any4 r/k/v）
  - `gemv_int8_rkv_stage1`（int8 r/k/v）

## 3. 关键 bug 修复

- **cuBLAS GEMM `CUDA_ERROR_ILLEGAL_ADDRESS (700)`**：
  `cublasGemmEx` 的 A/B/C 参数是**直接设备指针值**（`bd as *const c_void`），
  原代码误传 `&bd as *const u64 as *const c_void`（栈变量地址），把栈地址当设备地址传给 GPU。
  修复为直接传设备指针值（生产路径 + 诊断测试 `cublas_direct_gemm_probe` 两处）。

## 5. 关键设计决策

- **decode 走 CUDA graph、prefill 走 cuBLAS**：两条路径各自最优；graph 只包 decode 的固定
  kernel 序列（数据随 token 变，kernel 不变），prefill 的 GEMM 交给 cuBLAS tensor-core。
- **gemv 归约用 warp shuffle**：`__shfl_down_sync` 无跨 warp 同步，仅末次 1 次 `__syncthreads`，
  比共享内存 7 步树归约同步开销更小；数值因求和顺序不同可能有微小差异，实测为 bit-identical。
- **cuBLAS 失败安全**：`cublasSetStream` 失败即销毁句柄回退自定义 kernel；`CUBLAS_GEMM=0` 可
  保留句柄但 gemm 走自定义 kernel，隔离 cuBLAS gemm 与句柄污染。
